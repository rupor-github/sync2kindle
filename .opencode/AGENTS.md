# Agent Notes

## Project Shape

- Go module `s2k`; CLI entrypoint is `cmd/s2k/main.go`, producing binary `s2k`.
- Main sync flow is `sync.RunMTP` / `sync.RunUSB` / `sync.RunMail` in `sync/run.go`; action planning is isolated in `sync/prepare.go`.
- Device drivers are package-boundary implementations of the `sync.driver` interface: `files` for local FS, `mtp`, `usbms`, `mail`, and `history`.
- Linux MTP uses CGO with `pkg-config: libmtp`; CI installs `libmtp-dev`. Windows MTP uses COM/WPD and does not require CGO.

## Commands

- Preferred build/check command: `go tool task` (default task). It installs pre-commit hooks if `pre-commit` exists, regenerates `misc/version.go`, builds `build/s2k`, compiles tests, then runs staticcheck.
- Run all available tests: `go tool task test`.
- Run focused tests: `PACKAGES='./sync' go tool task test -- -run=TestPrepareActions` (comma-separate multiple packages in `PACKAGES`).
- Run staticcheck only: `go tool task lint`.
- Cross-build Windows dev binary from Linux: `go tool task debug-win`.
- Release build: `go tool task release`; release builds use `-mod=vendor`, so update `vendor/` with `go tool task vendor` after dependency changes.
- Keep module metadata consistent for both supported targets with `go tool task tidy`; it runs `go mod tidy` for linux-amd64 and windows-amd64.

## Build And Test Gotchas

- Project is using jj-vcs (not git).
- `Taskfile.yaml` assumes the host OS is Linux and sets `GOTOOLCHAIN=local+path`; use a local Go matching `go.mod` rather than relying on auto-download.
- `misc/version.go` is generated by `generate-project-version` and ignored by git. Do not hand-edit it; run a task that regenerates it.
- Some tests compile with CGO enabled via `compile-all-tests`; plain `go test ./...` is not equivalent to the default task.
- `thumbs/mobi` and `thumbs/kfx` tests use fixtures in `testdata/_Test.azw3` and `testdata/_Test.azw8`; they skip if fixtures are unavailable.
- Pre-push hook runs `trivy --exit-code 1 fs --ignore-unfixed .`; `pre-commit` installs hooks from `.pre-commit-config.yaml` during default/dev build tasks.

## Repo Conventions

- Config defaults come from embedded `config/config.yaml.tmpl`; `config.LoadConfiguration` overlays user YAML with known-field decoding plus sanitize/validate rules.
- `--debug` creates a report zip and may copy config/history/log artifacts, but `SecretString` is used to avoid leaking secrets in dumped config.
- History databases are per protocol/device/target and named by `history.GetName`; sync deliberately leaves device-side files not known in history untouched.
- Test data in `sync/prepare_test.go` and `objects/infoset_test.go` intentionally uses Windows-style drive paths with `/` so Linux tests exercise cross-platform path handling.
